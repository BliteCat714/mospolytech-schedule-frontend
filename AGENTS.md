# Текущий этап: только фронтенд

- Работаем исключительно в репозитории фронтенда. Бэкенд, его конфигурацию и данные не меняем.
- Для разработки используем локальный mock-режим. Тестовые данные и mock API можно менять под задачи интерфейса.
- Если интерфейсу нужны новые ручки, поля или другой формат данных, описываем требования в `docs/backend-requirements/README.md`. На текущем этапе реализуем нужное поведение только во фронтенде и моках.
- В требованиях явно отличаем существующий контракт API от предлагаемого. Для каждого предложения указываем сценарий интерфейса, метод и путь, параметры, примеры запросов и ответов, состояния ошибок и открытые вопросы, если они применимы.
- Запись требования не означает, что оно реализовано в бэкенде. Не переносим реализацию в соседний репозиторий без явной смены пользователем текущего ограничения.
