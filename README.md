# Расписание — фронтенд

React + TypeScript + Vite. Данные — реальное расписание rasp.dmami.ru через API бэкенда (`mospolytech-schedule-backend`, приложение `rasp`).

## Запуск

```sh
cp .env.example .env     # VITE_API_URL=http://localhost:8000/api
npm ci
npm run dev              # http://localhost:5173
npm run build && npm run lint
```
Бэкенд должен быть запущен (`python manage.py runserver`) и содержать импортированное расписание (`python manage.py import_rasp`). Всё вместе: `docker compose up -d --build` из корня проекта.

## Как это работает
- Вход: «Я студент» — выбор группы, «Я преподаватель» — поиск по имени. Профиль, открытое расписание и избранное хранятся в localStorage (`profile:v2`).
- Расписание: `GET rasp/groups/<номер>/lessons/`, `GET rasp/teachers/<id>/lessons/`, переключатель «Сессия» (`?session=1`). Занятия показываются по дню недели и периоду действия (`date_from…date_to`).
- Экспорт в календарь: кнопка «В календарь» скачивает `.ics` (`rasp/groups/<номер>/calendar/` или `rasp/teachers/<id>/calendar/`); для своего расписания добавляет физкультуру и выбранный проект (`owner`).
- Время пар: `GET rasp/pair-times/`.
- Кабинеты: `GET rasp/rooms/free/`. Физкультура: `schedule/pe/*`, запись привязана к идентификатору браузера (`clientId` в localStorage).
- Офлайн-режим с тестовым снимком (`VITE_DATA_SOURCE=mock`) удалён: данные были от старого генератора и несовместимы с реальным API.

## Генерация подготовленной нагрузки

Раздел `/generation` запускает настоящий решатель через backend и показывает
сохраненный результат. Его календарь использует время `TimeSlot` выбранного
запуска, а не словарь звонков опубликованного расписания `rasp`.

- `GET schedule/generation-options/` — доступные подготовленные периоды, группы,
  преподаватели и сетки. Группа в форме результата выбирает проекцию; расчет
  включает все группы периода.
  `default_semester_id` рекомендует текущий отдельный пример без ПД. Период
  просмотра определяется сохранённым run через существующий публичный API;
  новый default не меняет группу или подписи исторического результата.
- `POST schedule/generate/` — запуск с `clear_previous=false`. Существующий
  backend разрешает этот маршрут публично; интерфейс учитывает
  `authentication_required` каталога. Только если сервер явно требует доступ,
  показывает поля HTTP Basic (учетные данные только в памяти страницы).
- `GET schedule/schedule/groups/{id}/?run_id={id}` и аналогичный маршрут
  `teachers` — чтение проекции одного результата. Повторное открытие не вызывает
  решатель. Сетевой таймаут не приводит к автоматическому повтору POST.

Обычные пары и фиксированная ПД показаны раздельно в ответе и вместе в календаре.
У ПД видны точные интервалы, число участников данной проекции и заданный буфер
перемещения. Данные и ограничения подготовленного примера показаны в уведомлении
из API; интерфейс не объявляет тестовые проекты и студентов реальными и не
подставляет физкультуру, если она не включена в результат генератора.

Проверки: `npm run build`, `npm run lint`, `npm test` (Node.js 22.18+).
Тест адаптера проверяет сохранение буквального времени старого запуска и
персонального состава фиксированной ПД.

## ДПО и мероприятия

- `/dpo` — четыре шага, подключённые к существующему API генератора:
  программа и модуль, слушатели из БД, дисциплины и часы, запуск CP-SAT и
  сохранённые результаты. Клиентский mock-планировщик удалён.
  На шаге слушателей группы раскрываются со списком включённых студентов;
  добавление открывает поиск только среди остальных. Изменения сохраняются
  при составлении расписания. К готовому результату ведёт отдельная кнопка
  «Посмотреть расписание ДПО». В результате можно выбрать слушателя и сравнить
  его основные занятия с выбранным расчётом ДПО на одной сетке. Главная страница
  опубликованного расписания автоматически не меняется.
  Сервер строит недельный шаблон; часы должны делиться на число недель × 2.
  Произвольные календарные даты и чередование недель этот контракт не поддерживает.
- `/events` — в Vite dev-режиме последние анонсы с сайта Политеха через
  локальный прокси: автоматическая загрузка при открытии и раз в 15 минут, поиск
  среди первой страницы ленты, ручное обновление. В production используется
  существующий API каталога; серверная синхронизация описана в требованиях.
- Отдельный пункт поиска свободного времени убран; прежний адрес
  `/free-periods` перенаправляет в каталог мероприятий.

Вход администратора и формы управления каталогом мероприятий пока скрыты.
Серверные права доступа не менялись. ДПО требует staff-доступа по существующему
контракту. Для локальной проверки Vite проксирует `/__dpo-api/` в loopback-backend
и добавляет авторизацию только на серверной стороне. В `.env.local` задайте
`DPO_DEV_API_TARGET`, `DPO_DEV_USERNAME`, `DPO_DEV_PASSWORD` (имена также описаны
в `.env.example`). Файл не коммитится; пароль не попадает в браузер или сборку.
Прокси предназначен для локального dev-сервера, а не опубликованного приложения.
Production-сборка использует обычный `VITE_API_URL` и существующие серверные права.

Сохранение программы состоит из нескольких существующих CRUD-запросов и не
является одной серверной транзакцией. При ошибке интерфейс сохраняет ID подтверждённых
записей для повторения в этой вкладке; после сетевого сбоя запуска сначала проверьте
историю расчётов. Полная неизменяемость снимков и идемпотентность создания требуют
отдельного серверного контракта.
